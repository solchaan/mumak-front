# Mumak · Frontend

8마디 음악 아이디어를 작곡하고 간단히 녹음하는 웹 스케치북입니다. React + TypeScript + Vite를 사용하며, 소리는 브라우저 Web Audio API에서 생성합니다.

## 실행

Node.js 22.12 이상을 사용하세요. 두 저장소를 같은 상위 폴더에 두면 통합 테스트도 실행할 수 있습니다.

```sh
git clone https://github.com/solchaan/mumak-front.git
git clone https://github.com/solchaan/mumak-back.git
cd mumak-front
npm ci
npm run dev
```

http://127.0.0.1:5173 에 접속합니다. 포트가 사용 중이면 `npm run dev -- --port 5174`로 변경하세요. 서버 저장을 쓴다면 백엔드 `ALLOWED_ORIGINS`에도 변경한 출처를 추가하세요.

## 구현된 기능

- 8마디 / 4분의 4박자, 40–240 BPM, 16분음표 그리드
- 2마디씩 편집하는 피아노 롤: 클릭 추가, 드래그 이동, 우클릭 삭제, 길이·세기 편집
- 선택된 음표의 방향키 이동과 Delete/Backspace 삭제
- Soft keys / Warm pluck / Analog synth 웹 악기
- 킥·스네어·하이햇 패턴, 트랙별 볼륨과 음소거
- 오디오 시계 기반 예약 재생, 반복, 메트로놈, Space 재생/정지
- 마이크 한 트랙 녹음, 8마디 후 자동 종료, 수동 종료, 시작 위치 보정
- IndexedDB 자동 저장, 프로젝트 목록, 실행 취소/다시 실행
- JSON 프로젝트 백업·가져오기 (가져오기는 사본으로 생성)
- 전체 믹스 및 개별 트랙 WAV, 멜로디·드럼 MIDI 내보내기
- 악보 PDF 내보내기 (리드시트, A4, 브라우저 인쇄 대화상자로 저장)
- mumak-back 프로젝트 저장·목록·불러오기 연동

WAV는 44.1 kHz / 16-bit 스테레오이며, 8마디 + 1초 잔향으로 트랙의 시작점과 길이가 같습니다. 현재 볼륨·음소거를 반영합니다. MIDI는 음표·BPM·박자·드럼 채널을 포함하지만 악기 음색과 녹음은 포함하지 않습니다.

## 백엔드 연결

별도 터미널에서 mumak-back의 `npm start`를 실행하세요. 앱의 **프로젝트 서버**에서 서버 주소와 필요한 경우 API 토큰을 입력한 뒤 연결합니다. 토큰은 메모리에만 유지합니다. 브라우저 자동 저장과 서버 저장은 별개이며, 서버 저장은 버튼을 누를 때 실행합니다.

기본 주소는 http://127.0.0.1:3001 입니다. `.env.example`을 참고해 `VITE_API_URL`을 설정할 수 있습니다. VITE_ 변수는 클라이언트에 공개되므로 비밀 토큰을 넣으면 안 됩니다.

```sh
npm test
npm run build
# 브라우저 통합 테스트: ../mumak-back 체크아웃 필요
npx playwright install chromium
npx playwright test
# 설치된 Google Chrome을 사용하는 경우

```

통합 테스트는 포트 4178/3018, `.test-data/`와 가상 마이크를 사용합니다. 실제 마이크 품질·장치 지연·Safari 호환성은 수동 검증 대상입니다. CI는 단위 테스트와 프로덕션 빌드를 실행합니다.

## 구조와 현재 범위

- src/model.ts: 프로젝트 형식 v1 및 검증
- src/audio.ts: 합성 악기, 드럼, 재생 예약, 녹음, 오프라인 렌더링
- src/PianoRoll.tsx: 음표 편집
- src/storage.ts: IndexedDB와 프로젝트 API
- src/notation.ts, src/StaffEditor.tsx: 악보 표기, 코드 작성, 코드 추천 UI
- src/layout.ts, src/score.ts, src/ScoreSheet.tsx: 악보 배치와 VexFlow 조판(편집기·인쇄 공용), 인쇄용 리드시트
- src/harmony.ts: 코드 추천 요청 페이로드와 진행 적용
- src/midi.ts, src/wav.ts: 파일 인코딩
- src/main.tsx: 작업실 UI와 프로젝트 생명주기

첫 버전은 단일 사용자, 고정 8마디, C4–C6 범위, 오디오 한 트랙입니다. VST, 다중 녹음 테이크, 계정별 협업, 자동 타임스트레칭은 아직 지원하지 않습니다. 녹음 후 BPM을 바꾸면 음표 템포만 바뀌고 녹음 길이는 유지됩니다. 백그라운드 탭에서는 브라우저가 타이머나 오디오를 중단할 수 있습니다.

마이크에는 HTTPS 또는 localhost와 권한 허용이 필요합니다. 입력 지연은 장치마다 달라 녹음 후 시작 위치를 보정할 수 있습니다. 녹음 한도는 프로젝트당 20 MB입니다. 브라우저 데이터 삭제 시 프로젝트도 사라지므로 JSON 백업을 권장합니다.

프론트 정적 배포와 백엔드 운영 배포는 별개입니다. HTTPS 배포에서 원격 API를 연결하려면 HTTPS API와 정확한 CORS 출처가 필요합니다. Sites 설정은 `.openai/hosting.json`에 있으며 GitHub 저장소와 별도로 관리합니다.

백엔드: https://github.com/solchaan/mumak-back


## 오선지와 코드 작성

멜로디 영역의 **오선지 · 코드** 탭에서 피아노 롤과 같은 음표를 악보로 편집합니다.

- 음표 길이와 임시표(♮·♯·♭)를 선택하고 오선지를 클릭하거나, 입력 위치·음높이를 선택한 뒤 **음표 추가**를 누릅니다.
- 음표를 선택하면 방향키로 음높이·시작 위치를 바꾸고 Delete/우클릭으로 삭제할 수 있습니다. 길이·세기는 하단 도구에서 편집합니다.
- 악보는 보컬 리드시트 방식입니다. 오선지에는 멜로디만 적고, 코드는 기호로 악보 위에 붙습니다. 코드 구성음은 악보나 피아노 롤에 음표로 찍히지 않고, 재생·WAV·MIDI에서 기호로부터 자동 반주로 울립니다.
- **악보 표시**에서 멜로디만 / 멜로디 + 반주 / 반주만을 고릅니다. 반주는 코드 기호에서 자동으로 만들어진 큰보표(높은음자리표에 화음, 낮은음자리표에 루트 한 옥타브 아래)이며 직접 편집하지 않습니다. 표시 선택은 화면 설정이라 저장되지 않습니다.
- **반주 패턴**은 프로젝트에 저장됩니다. 기본값은 4/4박자 기준 4비트(박마다 한 번)이며, 2비트, 8비트, 지속(코드가 바뀔 때만)을 고를 수 있습니다. 재생·WAV·MIDI는 표시된 반주 보표와 같은 리듬으로 울립니다.
- 악보 위 코드 줄을 클릭하거나 입력 위치를 고른 뒤 코드 이름을 입력하고 **코드 추가**를 누릅니다. 코드는 다음 코드까지 이어지며, 겹치는 이웃 코드는 자동으로 잘립니다. 기호를 선택해 수정하거나 삭제할 수 있습니다.
- 지원 코드: 메이저, m, 7, maj7, m7, dim, dim7, m7b5, aug, sus2, sus4, 6, m6. 예: C, Am, G7, Bbmaj7, F#m7b5.
- 코드 이름 입력창에 글자를 치면 아래에 자동완성 목록이 열립니다. 입력한 글자를 포함하는 코드를 앞글자 일치 순으로 보여주고, 조표가 있으면 그 조의 다이어토닉 코드를 로마 숫자와 함께 맨 앞에 둡니다. ↑↓로 이동, Enter 또는 클릭으로 선택하며 선택한 코드는 미리 들립니다. Esc로 닫습니다.
- 높은음자리표, C4–C6, 기본위치 화음을 사용합니다. 박자 변경, 전위·슬래시 코드, 셋잇단음표, 악보 인쇄는 지원하지 않습니다. 세 겹 임시표가 필요한 Cbdim7/B#aug는 거부합니다.
- **조표**는 도구 모음에서 선택합니다. 장조 12개와 단조 12개(♯5개까지, ♭6개까지)를 지원하며 프로젝트에 저장됩니다. 조표를 정하면 악보 첫머리에 그려지고, 조표에 포함된 음은 임시표 없이 표시되며, 임시표 버튼이 **조표**일 때 입력하는 음은 조표에 맞는 음높이(예: G 장조에서 F → F♯)가 됩니다. 조표가 없는 음표는 조표 방향(♯/♭)으로 표기합니다. 조표는 코드 추천의 조성으로 고정되고 MIDI 조표 메타 이벤트로 내보냅니다.
- 빈 시간은 쉼표로, 마디를 넘거나 단일 음가로 나타낼 수 없는 길이는 붙임줄로 표시합니다. 편집용 악보는 16분음표 시간 간격으로 배치합니다.
- 코드 기호와 음이름 표기는 프로젝트 JSON과 서버 저장에 보존됩니다. MIDI에서는 코드 기호가 텍스트 이벤트로, 반주 화음이 2번 채널, 베이스가 3번 채널로 나갑니다. 이전 형식(코드가 음표를 생성하던 파일)을 열면 생성됐던 구성음 음표는 제거되고 기호만 남습니다.

### 악보 PDF 내보내기

**내보내기 → 악보 PDF**를 누르면 인쇄용 리드시트가 열립니다. 제목, 조표, BPM, 반주 패턴을 머리글로 두고 한 줄에 2마디씩 8마디를 그리며, 코드 기호와 마디 번호가 악보에 함께 인쇄됩니다. 멜로디만 / 멜로디 + 반주 / 반주만을 고른 뒤 **PDF로 저장**을 누르면 브라우저 인쇄 대화상자가 열리고, 대상을 "PDF로 저장"으로 고르면 벡터 PDF가 만들어집니다. 파일 이름은 프로젝트 이름을 따르고 용지는 A4 세로이며, 줄 사이에서만 페이지가 나뉩니다. 별도 PDF 라이브러리 없이 브라우저 인쇄 기능을 쓰므로 한글 제목도 그대로 들어갑니다.

### 코드 진행 추천

코드 입력 폼의 **코드 추천**을 누르면 입력 위치·길이를 기준으로 mumak-back의 `POST /api/harmony/suggest`가 조성을 추정하고 다음 코드 후보와 8마디 상용 진행을 돌려줍니다. 추천은 규칙 기반이며 외부 AI 서비스를 쓰지 않습니다.

- 요청에는 현재 음표와 코드만 보내고 녹음·제목은 보내지 않습니다. 프로젝트 서버 주소와 토큰은 **프로젝트 서버** 대화상자의 설정을 그대로 사용하며, 서버가 꺼져 있으면 오류 메시지를 표시합니다.
- 추천 칩을 누르면 해당 위치에 코드 기호가 바로 붙습니다. 같은 위치에 이미 코드가 있으면 교체하며, 실행 취소로 되돌릴 수 있습니다. 칩에 마우스를 올리면 추천 근거(예: V → I 진행, 멜로디 음 포함, 마침 코드)가 보입니다.
- **적용** 버튼은 조성에 맞춘 4코드 진행을 마디당 한 코드씩 8마디 전체에 붙입니다. 각 마디에 이미 있던 코드는 교체되고 멜로디 음표는 그대로입니다.
- 추천 아래에는 **현재 진행**의 로마 숫자(조성 밖 코드는 `?`)와 **코드 진행 팁**이 함께 표시됩니다. 팁은 같은 코드 반복, 마침 방식, 딸림·버금딸림 기능 부재, V → IV 역행, 조성 밖 코드, 3화음만 사용, 마디당 코드 밀도, 센 박 멜로디와 코드의 충돌을 짚고, I–V–vi–IV나 ii–V–I 같은 상용 진행을 알아보면 설명을 붙입니다. 공부용 안내이므로 의도한 효과라면 무시해도 됩니다.
- 조성 추정은 음표가 적을수록 불확실합니다. 추천 영역의 신뢰도를 참고하고, 결과가 어긋나면 코드를 몇 개 먼저 입력한 뒤 다시 추천을 받으세요.

VexFlow 악보 렌더러는 오선지 탭을 처음 열 때 지연 로딩합니다. 기존 v1 프로젝트는 빈 chords 목록으로 읽으며, 음표의 선택적 spelling과 코드의 noteIds를 검증합니다. 코드 저장에는 이번 백엔드 버전이 필요합니다.
